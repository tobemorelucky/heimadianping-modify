# AI 运营助手功能范围

## 1. 阶段定位

本文件定义 HM-DianPing Plus AI 运营助手首期实现边界。目标是用最小可用范围验证“自然语言问题 → 只读工具查询 → 有依据的运营回答”，不建设自动经营决策系统，也不改造现有核心业务链路。

当前阶段仅完成设计，不编写 Java、Python、配置、SQL、Lua 或部署代码。

## 2. 目标用户

### 2.1 首期用户

- 已登录且已绑定店铺的商家/店铺运营人员。
- 具备明确授权范围的平台运营人员。

### 2.2 非目标用户

- 未登录访客。
- 普通消费者的通用聊天场景。
- 需要跨商户查看数据但没有平台运营权限的用户。
- 以 AI API 为能力提供方的第三方开发者。

## 3. 首期实现范围

### 3.1 对话能力

- 支持中文单轮问题。
- 支持在一个请求内进行有限的多工具组合。
- 回答包含时间范围、统计口径和数据更新时间。
- 无权限、参数不足、无数据或上游失败时返回明确提示。
- 保留 `requestId` 和工具调用审计记录。

首期可以预留 `conversationId`，但不依赖长期记忆做业务判断；每次请求的身份与授权范围都重新从 Spring Boot 获取。

### 3.2 四个只读工具

| 工具 | 首期能力 | 核心限制 |
|---|---|---|
| 店铺信息查询 | 查询授权店铺基础信息、评分、销量和评论等概览 | 单次单店；字段白名单；对象级鉴权 |
| 订单统计 | 查询最多 90 天的订单趋势、用户数和状态分布 | 只返回聚合；固定统计口径；不返回个人信息 |
| 优惠券分析 | 查询券状态、价格、秒杀时段、库存及订单/核销表现 | 无曝光数据时不计算曝光转化率 |
| 热门数据分析 | 返回受控范围内的店铺排行榜和趋势线索 | 确定性指标；最多 20 条；平台范围需运营权限 |

### 3.3 服务范围

- Spring Boot 负责认证、授权、业务查询、聚合和字段裁剪。
- FastAPI 负责 AI 请求协议、错误映射和 LangGraph 接入。
- LangGraph 负责状态机、工具路由、有限重试和终止条件。
- LLM 负责意图理解、结构化参数生成和结果表述。
- Java/Python 首期使用内网 REST/JSON 通信。

### 3.4 非功能范围

- 用户、商户和服务级限流。
- Tool 调用、耗时、错误类型和 Token 使用量观测。
- 敏感数据最小化和日志脱敏。
- Tool Schema、Prompt、Graph 和模型版本记录。
- 固定问题集的正确性、安全性和故障场景评测。

## 4. 明确不实现范围

### 4.1 不提供业务写操作

首期不实现以下能力：

- 新增或修改店铺信息。
- 创建、发布、下架或修改优惠券。
- 修改秒杀库存、活动时间或消息模式。
- 创建、取消、退款、核销订单。
- 修改用户、评价、博客或关注数据。
- 直接删除或重建 Redis 缓存。
- 直接写入 Elasticsearch 索引。

Agent 不拥有任何数据库、中间件或通用代码执行权限。

### 4.2 不改造既有核心链路

- 不修改 Kafka 秒杀 Producer、Consumer、Retry/DLT 或 Redis Stream 回退。
- 不修改 Elasticsearch `/shop/of/name` 搜索链路。
- 不修改 Canal 店铺详情缓存失效链路。
- 不修改 Redis Lua、MySQL 表结构或现有业务事务。
- 不把 AI 服务放入秒杀、订单事务或缓存失效的同步路径。

### 4.3 不建设复杂 AI 平台

- 不实现多 Agent 协作。
- 不实现模型微调或自训练。
- 不实现长期自主记忆和用户画像推断。
- 不实现通用工作流设计器或动态加载任意 Tool。
- 不实现语音、图片、多模态输入。
- 不实现自主定时任务、主动营销或无人审批自动执行。
- 不以向量数据库或 RAG 作为首期必要依赖。

### 4.4 不承诺不存在的数据指标

- 没有曝光、点击、领取事件时，不输出对应漏斗和转化率。
- 没有成本数据时，不计算利润或 ROI。
- 没有历史快照时，不声称能够还原任意时点库存。
- 不用评分、销量相关关系推断经营因果关系。
- 不把 LLM 的建议描述为确定性经营结论。

## 5. 数据与权限范围

| 数据 | 是否可用 | 说明 |
|---|---|---|
| 店铺基础信息 | 是 | 仅授权店铺，字段白名单 |
| 店铺评分、销量、评论数 | 是 | 明确数据更新时间 |
| 优惠券定义与秒杀库存 | 是 | 仅授权店铺所属券 |
| 优惠券订单聚合 | 是 | 默认不返回订单明细和用户标识 |
| 用户手机号、支付账号 | 否 | 不传入 Python 或 LLM |
| 跨商户明细 | 否 | 平台运营也优先使用脱敏聚合 |
| 任意 SQL 查询结果 | 否 | 仅允许固定 Tool API |

权限判断必须由 Spring Boot 执行，模型、FastAPI 传入的角色或 shopId 不能作为唯一依据。

## 6. MVP 验收标准

后续进入实现阶段时，MVP 至少满足：

1. 四个 Tool 均有严格请求/响应 Schema 和独立单元测试。
2. 商家只能查询被授权的店铺，越权请求在 Java 层被拒绝。
3. 一个问题最多执行预设次数的 Tool Call，达到上限后能正常终止。
4. 正常、无数据、参数错误、无权限、Java 超时、LLM 超时场景均有可解释响应。
5. 回答中的关键数字可以追溯到 Tool Result，并包含统计时间与口径。
6. 日志可通过同一 `requestId` 串联 Spring Boot、FastAPI、LangGraph 和 Tool 调用。
7. AI 服务停机或异常不影响现有店铺、搜索、秒杀和 Canal 链路。
8. 不存在 Python/LLM 直连 MySQL、Redis、Elasticsearch、Kafka 或 Canal 的凭据。

## 7. 建议实施顺序

本文件不授权立即实现，后续经确认可按以下顺序推进：

1. 冻结 Tool Schema、统计口径和权限模型。
2. 在独立 Java AI Adapter 边界设计只读内部 API，避免侵入核心业务。
3. 建立独立 FastAPI 工程及 Java/Python 契约测试。
4. 实现单工具 LangGraph 流程，再逐步开放有限多工具组合。
5. 增加安全、超时、越权、无数据和提示注入测试。
6. 小范围灰度，只读观察审计数据后再评估 RAG 或写操作需求。

## 8. 后续候选能力

以下内容只列为演进方向，不属于首期承诺：

- 将运营规则、活动手册和 FAQ 建成 RAG 知识工具。
- 基于事件埋点补充曝光、点击、领取和完整转化漏斗。
- 增加可人工确认的运营建议草稿，但仍不自动执行。
- 对经过脱敏的聚合结果做短期缓存和离线报表。
- 建立离线评测集、人工评分和模型/Prompt A/B 测试。
